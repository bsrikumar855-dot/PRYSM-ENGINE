# PRYSM CLI & static report specification v1 (normative for M4)

Implements F-08 (CLI), F-09 (viewer → static report per DEC-10), F-03 (explanations), A-03, A-08, A-13 (CLI part), F-11 (simulation, reduced). Consumes `src/store` (`openStore`, `query`, `getEvent`, `eventsByDecision`, `verify`, `anchor`, `iterate`, `count`, `head`) and `src/core` (`loadPolicy`, `evaluate`). No runtime dependencies. Files: `src/cli/*.ts` + `src/cli/bin.ts` (backend-engineer), `src/report/*.ts` (frontend-engineer), tests `test/cli/*.test.ts`, `test/report/*.test.ts`.

**Hard limit stated up front (design consequence of privacy):** the store keeps keyed digests and `{type,len}` only, never argument values. Therefore **recorded traffic cannot be replayed against a new policy** (F-11 as originally written). `simulate` instead evaluates an explicit request file against one or two policies (§1.6). The report states this limit.

## 1. CLI (`node src/cli/bin.ts <command> ...`, also `package.json` `bin: prysm`)
Global: `--db <file>` (required where a store is read), `--key-path <file>` (default `<db>.key`; read-only commands open the store **read-only** and must not create a key file — if the key is missing they still work for everything except keyed-digest checks), `--json` (machine output), `--no-color`. Exit codes: `0` success; `1` verification/lookup failure (`verify-chain` not ok, `explain` unknown id); `2` usage/config error. Messages never echo argument values, keys or file contents (paths only as given by the operator).
1. `validate <policy.json> [--sha256 <hex>]` — `loadPolicy`; prints `valid  <policy_version>  rules=<n> tools=<n> mode=<mode>`; exit 2 with the `PolicyError` code+path on failure (no values). `--sha256` must equal the SHA-256 of the file bytes else exit 2.
2. `events --db F [--kind k] [--tool t] [--session s] [--effect e] [--after-seq n] [--limit n=50, max 1000] [--count] [--json]` — `--count` prints a single integer = the number of rows matching the filters (no limit applied); without it prints one line per event: `seq  ts_iso  kind  effect/enforcement  reason_code  tool  decision_id(8)` (all fields escaped for terminals: control characters and ANSI escapes replaced by `?`, U+2028/2029/0085 escaped). `--json` prints JSON lines (store fields as stored; no raw values exist). Empty store: prints nothing (exit 0) / `0` for `--count`.
3. `explain <decision_id> --db F [--policy <file>]` — exit 0 and prints, for a known id: the decision row fields (effect, enforcement, reason_code, rule_ids, policy_version, risk, session_tainted, provenance_asserted labels, latency_us, `args_redacted` as stored, `will_execute`), the linked `tool_result` row(s) (status, error_class, result_type, result_len), any `dropped_before` note, a one-line verdict in plain language (`BLOCKED by rule(s) … because …` / `ALLOWED by rule(s) …`) and, when `--policy` is given **and its `policy_version` equals the row's**, the matched rules' effect, `reason_code` and a human summary of their `match` clauses (tools, arg predicates, provenance, scopes, session_tainted). A policy file whose version differs ⇒ warning line `policy version differs; rule detail not shown` (never show rules from a different version). Unknown id ⇒ exit 1 with `no such decision`. `--json` prints one JSON object. Rows that are not decisions (id of a tool_result etc.) ⇒ exit 1 `not a decision`.
4. `verify-chain --db F [--anchor <file>] [--expect-pruned <file>] [--allow-pruned] [--json]` — runs `store.verify` with: anchor parsed from a JSON file (the output of `anchor`, or a `{"prysm":"anchor",...}` sink line); `--expect-pruned` file = JSON array (or JSON-lines) of `{through_seq,last_hash}` or `{"prysm":"checkpoint",...}` sink lines; prints `OK` or each error/warning as `error|warning seq=<n> code=<code>`, plus head seq/hash; exit 0 only when `ok`; warnings alone keep exit 0; `--allow-pruned` documented as development-only. Malformed anchor/expected files ⇒ exit 2 (never silently ignored).
5. `anchor --db F [--out file]` — prints (and optionally writes, mode default) the store anchor JSON `{genesis_hash, head_seq, head_hash, ts_ms}`; document: store it where an attacker with DB access cannot rewrite it.
6. `simulate --policy A.json [--policy-b B.json] --requests file.jsonl [--json]` — file lines are request objects `{tool, args, ctx}` (the guard's pre-snapshot shape; optional `id`); evaluates each with `evaluate()` against A (and B) and prints `id  A:<effect>/<reason>  [B:<effect>/<reason>]  [CHANGED]`; with B prints a summary of changed decisions (permit→deny and deny→permit counts, listed by id). Invalid lines are reported with their line number and counted, never aborting the run; exit 0 even with changes (changes are information), exit 2 for unreadable files. Max file 10 MiB, max 100 000 lines.
7. `report --db F [--policy <file>] [--out report.html] [--max-events n=500, max 5000] [--anchor <file>] [--expect-pruned <file>] [--title t]` — builds the static report (§2) and writes it (default `prysm-report.html`; refuses to overwrite a file not created by `report` unless `--force`, detected by a marker comment). Exit 0 on success even if the chain verification inside the report is not ok (the report shows it prominently); exit 2 on unreadable store.
8. `help`/no args prints usage, exit 2 for unknown commands.

## 2. Static report (`src/report`)
API: `buildReportData(store, opts): ReportData` and `renderReportHtml(data): string` (pure, deterministic for the same data; the generation timestamp is passed in `data.generated_ms`, never read inside the renderer). Output is **one self-contained HTML file**: no JavaScript, no external requests (no `http://`/`https://` URLs anywhere, no fonts/images from the network), inline CSS only, `<meta http-equiv="Content-Security-Policy" content="default-src 'none'; style-src 'unsafe-inline'; img-src data:; base-uri 'none'; form-action 'none'">`, `<html lang="en">`, a descriptive `<title>`, `<meta name="viewport" content="width=device-width, initial-scale=1">`, semantic landmarks (`header`, `main`, `section` with headings, tables with `<caption>` and `<th scope>`), keyboard-friendly in-page anchors, colour tokens defined once with light and dark (`prefers-color-scheme`) themes, contrast ≥ 4.5:1 for text in both, no information conveyed by colour alone, layout works at 360 px width without horizontal page scroll (tables scroll inside their own container), 16 px gutters. **Every value from the store is HTML-escaped (`& < > " '` and control characters/U+2028/2029/0085) — events carry attacker-influenced strings (tool names, session ids, reason codes, args_redacted keys).** No `innerHTML`, no inline event handlers, no `<script>`. A marker comment `<!-- prysm-report v1 -->` begins the file.
Sections (all computed from real stored rows only; no seeded/simulated data anywhere):
1. **Header & integrity**: title, generated time (ISO), db file name (basename only), head seq/hash (abbrev + full in `title` attribute), schema version, **verification result** (OK / FAILED with error list; warnings listed; whether an anchor/expected-checkpoint was supplied; a plain notice when no anchor was supplied: "tail truncation and full rewrites are not detectable without an external anchor"), key protection status (`keyProtection()` when available), proxy/guard posture from the newest `proxy_config` row (flags, counts) and `proxy_client` row.
2. **Overview metrics** (counts from the full store, not just the displayed window): events by kind; decisions by effect and by enforcement; **deny rate** = denied / decisions; decisions by public reason class; top denied tools (top 10) and top rules (from `rule_ids`, top 10); sessions count; tainted-session decision share; fail-open indicator (sink lines are not in the store, so state "see stderr"); dropped-event counters (sum of `outcome.dropped_before`); tool-result outcomes (ok/error/timeout counts).
3. **Latency (enforcement overhead)**: p50/p95/p99/max of `latency_us` over decision rows (nearest-rank), with the n and a caveat line: "decision time only (policy evaluation in-process), measured by the guard; not end-to-end latency". Empty ⇒ "no data".
4. **Policy versions & activations**: table from `policy_activate` rows (seq, time, event (`activation`/`tools_replaced`/`proxy_config`/`proxy_client`), policy_version (abbrev), mode, rule_count, tool counts) ordered by seq; the version used by the most decisions highlighted textually.
5. **Decisions explorer (window)**: the newest `max-events` decision rows, each row linking (in-page `#d-<id8>`) to a detail block showing the same facts as `explain` (§1.3, using `--policy` rule detail when versions match), with the linked result row(s); filter-free (no JS) but with a plain-language legend.
6. **Event log (window)**: newest `max-events` rows of all kinds, columns seq, time, kind, effect/enforcement, reason, tool, decision id.
7. **Limits & notes**: states that argument values are not stored (so no replay), that provenance is host-asserted, that `latency_us` is in-process, that false-positive/negative rates are **not available from the store** (they come from the labelled benchmark in `eval/`, M5), that the report is a snapshot at generation time, and the truncation note when the window omitted rows (`showing N of M`).
**Empty store**: every section renders a clear empty state (e.g. "No events recorded yet"), metrics show 0/“no data”, the verification shows OK (empty chain) — never placeholder numbers.
**Size**: if rendering would exceed 8 MiB the window shrinks automatically and the notice states it.

## 3. Required tests (acceptance evidence)
CLI (real process via `spawn`): `validate` ok/fail/sha mismatch; `events` filters, `--count` equals the number of rows from an independent query, terminal escaping of hostile tool names (ANSI/CR/newline/U+2028), empty store; `explain` known decision (blocked and allowed, with and without `--policy`, version-mismatch warning, no rule detail from a different version), unknown id ⇒ exit 1, a tool_result id ⇒ exit 1, `--json` shape, **A-03**; `verify-chain` ok / tampered row / tail truncation with and without anchor / forged-checkpoint with `--expect-pruned` / malformed anchor file ⇒ exit 2 (**A-13 CLI part**); `anchor` output equals `store.anchor()`; `simulate` one/two policies, changed counts, invalid lines, size caps; `report` writes a file with the marker, refuses to overwrite foreign files, `--force`; read-only commands do not create a key file or modify the DB (compare DB bytes/mtime before/after, and no `-wal` growth beyond what opening requires — assert row count and `head()` unchanged); usage errors exit 2 with no values echoed.
Report: **A-08** empty store ⇒ empty states, after a real guard/proxy run the displayed event count and the overview totals equal `events --count` / an independent store query; **XSS** — events whose tool/session/reason fields contain `<script>`, `"><img onerror>`, `javascript:`, U+2028, ANSI, RTL override are present only as escaped text (assert no raw `<script`/`onerror=` in output, parse with a minimal HTML check); no `http://`/`https://` substrings (except none) and no `<script`; CSP meta present; `lang`, `title`, `viewport`, one `h1`, table captions; determinism (same data ⇒ byte-identical output); 5000-row window stays within the size cap; tampered DB ⇒ report shows FAILED with the error codes; anchor supplied vs not (notice text); latency percentiles correct against an independently computed nearest-rank on a fixture; metrics (deny rate, top tools/rules) equal an independent recount from `store.iterate`; light/dark tokens present and (static check) the declared text/background pairs meet 4.5:1 (compute from the CSS tokens in the test).

## 4. v1.1 amendments (DEC-33; from the blind M4 test plan, items 1-28). These supersede earlier text where they conflict.
**CLI**
1. **Output path safety (--out).** `report --out` and `anchor --out` write via a temp file in the same directory followed by an atomic rename, never following links. They refuse (exit 2) when the target, after realpath resolution of the existing path (or of its parent directory plus basename if it does not exist), equals the DB, its `-wal`/`-shm`, the key file, the `--policy` file, or any `--anchor`/`--expect-pruned` input file; when the target is a symlink, a device name (CON, NUL, COM1...), contains an NTFS stream (`:` after the drive prefix) or exists but is not a regular file. An existing regular file is overwritten only when (a) for `report`: it begins with the report marker, or `--force` is given; (b) for `anchor`: `--force` is given. `--force` never overrides the protected-path or link refusals.
2. **Read-only open.** Read-only commands (`events`, `explain`, `verify-chain`, `anchor`, `report`) use `openStore({ readOnly: true })`: SQLite read-only mode, `query_only`, **no key load or creation, no meta writes (no `prune_open` reset)**, `keyProtection()` returns `"unknown"`. Tests assert the table row count and `head()` are unchanged and that no key file was created (never compare DB file bytes: WAL checkpoints legitimately change them). Keyed-digest facilities (`hmac`) are unavailable in read-only mode; nothing in M4 needs them.
3. **explain/report wording for monitor_only.** The verdict derives from effect AND enforcement: `enforcement=enforced, effect=deny` ⇒ `BLOCKED by ...`; `enforced, permit` ⇒ `ALLOWED by ...`; `monitor_only, deny` ⇒ `WOULD BE BLOCKED (monitor_only: the tool ran) by ...`; `monitor_only, permit` ⇒ `ALLOWED (monitor_only) by ...`.
4. **Anchor/expected files: syntax first.** `--anchor` and `--expect-pruned` files are parsed and shape-validated by the CLI before verification; unreadable, oversized (> 1 MiB), malformed JSON or wrong-shaped content ⇒ exit 2 and nothing is verified. A well-formed anchor that does not match the chain ⇒ `verify-chain` exit 1.
5. **File formats.** `--anchor <file>`: the file contains exactly one JSON object (the `anchor` command's output, or a single sink line `{"prysm":"anchor",...}`). `--anchor-log <file>`: a mixed log; uses the newest line that parses as a JSON object with `prysm == "anchor"` and is not prefixed `[server] `; other lines are ignored (error if none). `--expect-pruned <file>`: a JSON array/object or JSON lines of `{through_seq,last_hash}` / `{"prysm":"checkpoint",...}`; `--expect-pruned-log <file>`: all non-`[server]` lines with `prysm == "checkpoint"`.
6. **events.** Ascending `seq` by default; `--tail` selects the newest N rows (printed ascending); `--limit` must be an integer 1..1000 else exit 2; `--count` ignores `--limit` and, with `--json`, prints `{"count":n}`.
7. **--json escaping.** Every `--json` line escapes U+2028, U+2029 and U+0085 as ` `, ` `, `\u0085`.
8. **Terminal escaping.** In all human output (stdout and stderr, including ids, paths and tool names) replace `\p{Cc}`, `\p{Cf}`, `\p{Zl}`, `\p{Zp}` and lone surrogates with `?`. The CLI emits **no ANSI colour codes at all**; `--no-color` is accepted as a no-op.
9. **Exit codes.** `0` success (including `help`, a successful `report`, `simulate` with changes, and a closed pipe such as `| head` which ends quietly); `1` verification failure or lookup miss only (`verify-chain` not ok, `explain` unknown/ambiguous id or non-decision row); `2` everything else: usage errors, unknown command, no args, unreadable/missing/unopenable store or files, malformed anchor/expected files, invalid `--limit`, overwrite/path refusals, `simulate` size-cap exceeded (no partial output), `--policy` unreadable.
10. **explain ids.** Accepts a full id or a unique prefix of at least 8 characters; an ambiguous prefix ⇒ exit 1 (`ambiguous id`, count only).
11. **JSON schemas.** `explain --json`: `{ decision, results: [], verdict, warnings: [], rules: [] | null }`. `verify-chain --json`: `{ ok, errors: [{seq,code}], warnings: [{seq,code}], head_seq, head_hash, checkpoints: [] }`. In `--json` mode all warnings live in these arrays and stdout is exactly one JSON document; nothing else is written to stderr except fatal usage errors.
12. **simulate.** An *invalid line* is a JSON parse error or a non-object line; core `invalid_request`/`invalid_args` results are normal decisions. `id` defaults to the 1-based line number; blank lines are skipped; a line is `CHANGED` when effect **or** `reason_code` differs between A and B; duplicate JSON keys follow `JSON.parse` (last wins, documented); exceeding the file or line cap ⇒ exit 2 with no partial output.
13. **verify-chain output** groups informational warnings (`key_colocated`, `key_unprotected`, `anchor_pruned`, `history_pruned` when expected, `prune_flag_reset`) under a `notes` heading in plain mode; they never change the exit code.
**Report**
14. **Document skeleton.** The file starts with `<!doctype html>` immediately followed by the marker comment `<!-- prysm-report v1 -->` (detectable within the first 200 bytes), then `<html lang="en">`, `<meta charset="utf-8">` first in `<head>`; no BOM.
15. **Escaping scope.** Escape every non-literal string: store values, policy-derived text (rule summaries, names), `--title`, the db basename, `clientInfo`. Escape `& < > " '`, `\p{Cc}`, `\p{Cf}` (bidi controls shown as `\uXXXX`), `\p{Zl}`, `\p{Zp}`, lone surrogates. The "no `http://`/`https://`" and "no `<script`" checks apply to **markup** (element names, attribute values, CSS), not to escaped text content. Hostile-string tests build rows with raw `store.append` (the guard and proxy cannot store hostile tool names because policy identifiers are restricted; real vectors are clientInfo, forged DBs, `--title`, db names and policy text).
16. **Metric definitions.** *Denied (enforced)* = decision rows with `effect=deny` and `enforcement=enforced`; *Would-be denied (monitor_only)* = `effect=deny` and `enforcement=monitor_only`, reported separately. **Deny rate** = denied(enforced) / decisions with `enforcement=enforced`, one decimal with the counts shown (`6 of 14, 42.9%`), `no data` when the denominator is 0. *Reason classes*: stored core reason codes shown raw, grouped for readability as allowed (`permitted`), denied (`denied_by_rule`, `default_deny`, `tainted_session`), unknown tool, invalid request (`invalid_args`, `invalid_request`, `limit_exceeded`), unavailable (`engine_error`, `audit_unavailable`). *Top tools*: tool names of enforced denies (excluding `"?"` pre-evaluate rows shown as "unknown tool names (hashed)" count); *top rules*: ids from `rule_ids` of enforced denies, excluding the truncation marker `…+N`; ties broken by count descending then name ascending. *Most-used policy version*: count descending then version ascending. *Sessions* = distinct non-null `session_id` among decision rows. *Latency* n counts non-null finite non-negative integers only; percentile p = sorted[ceil(p*n/100) - 1] (nearest rank, integer math). Tainted share = decisions with `session_tainted=1` / decisions.
17. **Scan coverage.** Metrics are computed by a chunked scan (1000 rows per `query`) of at most `scanLimit` newest rows (default 2 000 000, option and `--scan-limit`); when the store is larger the report states "metrics cover the newest N of M rows". Within the scan "counts from the full store" holds.
18. **Bounded sections and size.** Section 4 (policy activations) shows the newest 200 rows plus "showing N of M". If the output would exceed 8 MiB the generator halves the explorer/log windows (max-events), then the activation window, deterministically, down to 0, and finally renders a minimal "report too large" page that still includes the integrity verdict and totals.
19. **Contrast test convention.** CSS custom properties are named `--fg-*` (text) and `--bg-*` (backgrounds); the test checks every `--fg-*` against every `--bg-*` it can appear on for both themes (a `--on-*` pairing is documented in a CSS comment per token if narrower); text may not use `opacity`, `rgba()` with alpha < 1, or `color-mix()`.
20. **Visible full hashes.** Head hash, genesis hash, anchor and checkpoint hashes are printed in full in visible wrapping `<code>` elements; `title` attributes are supplementary only.
21. **Scrollable regions.** Each table scroll container has `role="region"`, `aria-labelledby` pointing at the caption id, and `tabindex="0"`.
22. **Anchor ids.** Detail blocks use `id="d-<seq>"` (the unique store seq); links use `#d-<seq>`.
23. **Key protection.** Shown as `unknown (read-only report)` when the store is opened read-only.
24. **Reproducibility.** The report states `generated_ms` (ISO) and the head seq/hash it covers; identical data and `generatedMs` yield byte-identical output.
25. **Test note.** The `anchor` command test compares `genesis_hash`, `head_seq` and `head_hash` (not `ts_ms`).

## 5. v1.2 amendments (DEC-34; M4 gate pass 1: security-engineer M4-01..03, critical-reviewer MAJOR-1 + minors, QA black-box, lead browser check). Supersede earlier text where they conflict.
**Data contract (fixes the "permit rule named as the cause" defect)**
1. **Decision rows record the deny/permit split.** The guard writes `outcome.deny_n` (integer, number of deny-rule ids at the start of `rule_ids`; `rule_ids` stays "deny ids first, then permit ids") on every decision row it writes (including pre-evaluate and `denyUnexposed` rows, where it is 0). AUDIT-SPEC §2.3 is amended accordingly. Rows without `deny_n` (written before this change) are "legacy rows".
2. **Who is named as the cause of a block.** For `denied_by_rule` rows: with `outcome.deny_n` present, the cause is the first `deny_n` ids; else with a **same-version policy** the cause is the ids whose rule effect is deny; else (legacy row, no matching policy) the wording is `A deny rule matched. All matched rules, deny rules listed first: <ids>` and the row is excluded from the top-rules metric (the report states how many rows were excluded: "n rows lack the deny/permit split"). Permit ids are never presented as a cause. The CLI `explain` and the report implement the same precedence (backlog T-6.7: share one module).
3. **Top rules** counts only deny-cause ids determined by item 2 (rows with `reason_code=denied_by_rule`, `enforcement=enforced`); the `…+N` truncation marker is excluded.
**CLI**
4. `--out` refuses any basename ending in `.` or a space (M4-01), in addition to the §4.1 refusals.
5. **Schema allow-list on open (M4-03; applies to every open, read-only or not).** After opening, the store checks `sqlite_master`: `events` and `meta` exist as `table`; no `view`, no virtual table; no unexpected trigger bodies beyond the two append-only triggers (compare name and expected SQL text prefix); and sets `PRAGMA trusted_schema=OFF`. Violation ⇒ `StoreError corrupt` ⇒ CLI exit 2 within milliseconds (a forged recursive view must not be queried).
6. **Anchor/expected files.** A leading BOM (U+FEFF) is **not** stripped: it is malformed ⇒ exit 2 (QA). `--expect-pruned <file>` parses the whole file as JSON first (array or single object, pretty-printed allowed); if that fails, it parses JSON lines; otherwise exit 2. The report-overwrite marker check requires the file to **start with** `<!doctype html><!-- prysm-report v1 -->` (after at most a BOM-less start; no leading whitespace), not merely contain the marker.
7. **`anchor` verifies first.** `anchor` runs `verify` and refuses (exit 1, message names error codes only) when the chain has errors, unless `--no-verify` is given; with warnings only it proceeds and prints them as notes. Usage text documents `--opt=value` for values that start with `--`. `--scan-limit <n>` is accepted by `report` (default 2 000 000, min 1000) and passed to `buildReportData`; `-wal`/`-shm` side files left by read-only opens are documented (README, usage text), not suppressed (M4-02).
8. Tests that must exist and fail without their feature: `--limit 1001` exits 2; non-regular-file/dir target refusal; symlink refusal (skipped with a visible reason when the OS denies symlink creation); trailing dot/space `--out`; schema allow-list (a DB whose `events` is a view exits 2 quickly); BOM anchor exit 2; pretty-printed `--expect-pruned` object; marker-must-start rule; `anchor` refuses a tampered chain and `--no-verify` overrides; `PRAGMA query_only` (assert a write through the read-only connection is rejected by SQLite even if the JS flag were bypassed, via a test seam or direct raw read-only connection check).
**Report (design and content)**
9. **Banner honesty.** The verdict banner shows the warning count (`2 warnings`), states `Development flag: pruned history accepted without an expected checkpoint` when `allowPruned` was used, and when metrics cover only part of the store the header summary shows `Metrics cover the newest N of M rows` directly under the summary strip (not only in Overview).
10. **No heavy side stripe.** Replace the 14 px left border on the FAILED banner with a uniform 2 px border plus the bold word FAILED; contrast stays tested.
11. **Browser-check fixes.** In-page contents links are at least 24 px high (padding; 44 px under 480 px width); remove the stray period after the head hash (restructure the sentence so no punctuation sits alone on a line); remove raw `generated_ms` from visible text (keep the ISO time in a `<time datetime>` element; ms may stay in a `data-` attribute); **sessions**: count distinct non-null `session_id` values that do not start with `eph-` as "Named sessions" and report "Ephemeral per-call sessions: n" separately (guard-issued ephemeral ids are `eph-<id8>`).
12. **Pre-flight tests scan sources.** The dash/card/eyebrow/colour bans run over the rendered output of **all code paths** (normal, empty store, failed verification, truncated scan, "too large" page, every `CODE_HELP` entry) **and** over `render.ts`/`build.ts` source text (no U+2013/U+2014, no class names containing `card`, `tile`, `pill`, `badge`, `eyebrow`). A test proves permit ids never appear after "BLOCKED by" and that the truncation marker is excluded from top rules.
