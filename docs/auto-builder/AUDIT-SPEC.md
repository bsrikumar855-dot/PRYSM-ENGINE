# PRYSM audit store & guard specification v1 (normative for M2)

Implements DEC-01 (in-process half), DEC-03, DEC-04, DEC-05, DEC-06 and SECURITY-REVIEW items P-02, P-03, P-07, P-08, P-10, P-16, P-19, P-21 and F-03. Consumes `src/core` (POLICY-SPEC v1.3). Files: `src/store/*.ts`, `src/guard/*.ts`. `src/core` must not import store or guard.

## 1. Store (`src/store`)

`openStore(opts: { path: string, hmacKey?: Uint8Array, busyTimeoutMs?: number (default 2000), synchronous?: "FULL"|"NORMAL" (default FULL) }) → Store`. Uses `node:sqlite` `DatabaseSync` only, WAL, `PRAGMA synchronous=<opt>`. Narrow interface (so the backend can be swapped):
- `append(ev: NewEvent): StoredEvent` — synchronous, durable (see §1.3). Throws `StoreError{code}` (`busy`, `io`, `invalid_event`, `corrupt`) with **no values in messages**.
- `appendBestEffort(ev): StoredEvent | null` — never throws; on failure returns null and writes one JSON line `{"prysm":"audit_write_failed","code":...,"kind":...,"id":...}` to the secondary sink.
- `iterate({ afterSeq?: number, limit?: number }): StoredEvent[]` (read-only connection semantics), `head(): { seq: number, hash: string } | null`, `count(): number`.
- `verify(opts?: { anchor?: Anchor }): VerifyResult`, `anchor(): Anchor`, `checkpointAndPrune(beforeTsMs: number): { pruned: number, checkpointSeq: number }`, `close()`.
- `hmac(label: "args" | "user" | "result", data: string): string` (hex) — the single keyed-digest facility (§1.5).

### 1.1 Schema (schema_version 1)
`meta(key TEXT PRIMARY KEY, value TEXT)`: `schema_version`, `genesis_hash`, `created_ms`, `key_id` (first 8 hex of SHA-256(hmacKey)), `prune_open` ('0'/'1').
`events`: `seq INTEGER PRIMARY KEY AUTOINCREMENT, id TEXT NOT NULL UNIQUE, ts_ms INTEGER NOT NULL (UTC ms), kind TEXT NOT NULL, execution_id TEXT, session_id TEXT, agent_id TEXT, user_hmac TEXT, tool TEXT, effect TEXT, enforcement TEXT, rule_ids TEXT (JSON array), reason_code TEXT, policy_version TEXT, request_digest TEXT, args_hmac TEXT, args_redacted TEXT (JSON), risk TEXT, latency_us INTEGER, session_tainted INTEGER, provenance_asserted TEXT (JSON), model_meta TEXT (JSON), outcome TEXT (JSON), decision_id TEXT, engine_version TEXT, prev_hash TEXT NOT NULL, hash TEXT NOT NULL`.
`kind` ∈ `decision`, `tool_result`, `policy_activate`, `checkpoint`. `enforcement` ∈ `enforced`, `monitor_only`. Triggers `events_no_update` (always) and `events_no_delete` (unless `meta.prune_open='1'`) raise `append-only`. Triggers are a speed bump, not a security control (documented).

### 1.2 Hash chain (tamper-*evident*)
`genesis_hash = sha256("prysm-genesis-v1")` hex. For each row: `hash = sha256_hex( prev_hash + "\n" + JCS(row_without_hash) )` where `row_without_hash` is the row object with **all columns except `hash`**, JSON columns parsed to values, `null` for absent, using core `jcs()`. `prev_hash` of seq 1 is the genesis hash.

### 1.3 Append
One transaction: `BEGIN IMMEDIATE`; read tail (`seq`, `hash`); compute `seq = tail.seq + 1` implicitly via AUTOINCREMENT but the hash preimage must include the *assigned* seq (so insert, read `last_insert_rowid`, update is forbidden by trigger — instead compute `seq = (SELECT COALESCE(MAX(seq),0)+1)` inside the same IMMEDIATE transaction and insert it explicitly); `COMMIT`. Busy beyond `busyTimeoutMs` ⇒ `StoreError busy`. A single-writer discipline via `BEGIN IMMEDIATE` guarantees a linear chain for multiple processes. Size caps: every text field ≤ 256 chars (truncate with `…[trunc]`), every JSON column ≤ 4 KiB serialized, whole row ≤ 16 KiB; oversize JSON is replaced by `{"truncated":true,"bytes":N}`. All strings are stored as JSON-encoded data; control characters and newlines are preserved only inside JSON escapes (log-injection safe, P-10). `ts_ms` comes from an injectable clock (default `Date.now`) and is **not evidence of time**.

### 1.4 Verify / anchor / prune
`verify()` returns `{ ok: boolean, count, head_seq, head_hash, pruned_through: number|null, errors: [{seq, code}], warnings: [{seq, code}] }`. Errors: `hash_mismatch`, `prev_mismatch`, `seq_gap`, `bad_genesis`, `unexpected_first_row` (first remaining row must be seq 1 with genesis prev, **or** a `checkpoint` event whose `outcome.pruned_last_hash` equals its `prev_hash`), `anchor_mismatch`, `schema_version`. Warnings: `outcome_unknown` — a `decision` row with `effect='permit'` and `enforcement` any, for a tool that was executed, but no `tool_result` row with `decision_id` = that row's `id` (this is how a crash between decision and result is surfaced; only decisions older than the newest row by ≥1 row are flagged, never the tail row in flight). `anchor()` → `{ head_hash, count, head_seq, ts_ms }` (print/export it somewhere an attacker with the DB cannot rewrite); `verify({anchor})` additionally requires a row with `seq == anchor.head_seq` and `hash == anchor.head_hash` (detects truncation and full rewrite). `checkpointAndPrune(beforeTsMs)`: one transaction: set `prune_open='1'`, append a `checkpoint` event (`outcome: { pruned_through_seq, pruned_last_hash, pruned_count }`), delete rows with `ts_ms < before` **and** `seq <` checkpoint seq, set `prune_open='0'`; rolls back wholly on error. The chain verifies from the checkpoint.

### 1.5 Keyed digests (P-08)
An install key (32 random bytes) is read from `opts.hmacKey` or from `<path>.key` (created with random bytes if absent; documented that its protection is the OS user's file ACL). `hmac(label, data) = HMAC-SHA256(key, label + ":" + data)` hex (first 32 hex chars stored is fine; document). Plain unsalted hashes of argument values must never be stored. `request_digest` from core is a *plain* SHA-256 of the NFC snapshot and therefore **must not be stored for low-entropy requests** — store `args_hmac` and set `request_digest` to `hmac("request", core_request_digest)` instead.

### 1.6 Redaction choke point (P-08)
`redactArgs(args, opts?: { rawFields?: string[] })` is the only function allowed to produce `args_redacted`. Default output per arg: `{ type, len }` (`len` = code points or array length) — **no values**. A field listed in `rawFields` is stored as a string truncated to 200 chars after secret masking (patterns: `sk-[A-Za-z0-9]{16,}`, `AKIA[0-9A-Z]{16}`, `ghp_[A-Za-z0-9]{20,}`, `-----BEGIN [A-Z ]*PRIVATE KEY-----`, `Bearer [A-Za-z0-9._-]{16,}`, JWT-shaped `eyJ…\..+\..+`, `password=`-style assignments → `«masked»`). Errors, secondary-sink lines, stack traces and `outcome` never contain argument or result values (types, lengths, HMAC digests, error class names only).

## 2. Guard (`src/guard`)

```ts
createGuard({ policy: LoadedPolicy, store: Store, agentId: string, tools: Record<string, ToolFn | { fn: ToolFn, taintsSession?: boolean }>,
              secondarySink?: (line: string) => void /* default process.stderr.write */, rawFields?: Record<string, string[]>, clock?: () => number }): Guard
Guard = { call(tool: string, args: unknown, ctx?: CallContext): Promise<GuardResult>, session(sessionId?: string): GuardSession, close(): void }
GuardSession = { id: string, taint(reason?: string): void, readonly tainted: boolean, call(tool, args, ctx?): Promise<GuardResult> }
CallContext = { userId?: string, scopes?: string[], provenance?: Record<string, string[]>, sessionTainted?: boolean, sessionId?: string }
GuardResult = { ok: true, value: unknown, decision_id: string }
            | { ok: false, blocked: true, decision_id: string, reason_code: "denied"|"unknown_tool"|"invalid_request"|"unavailable" }
            | { ok: false, blocked: false, decision_id: string, error: "tool_error" }
```
- `agentId` is fixed at creation. `CallContext` is validated strictly (unknown keys or an `agentId` key ⇒ blocked `invalid_request`). The guard builds core `ctx` itself; **provenance and taint are never read from `args`**. Per-call ctx is copied and frozen before any `await`; no shared mutable state between concurrent calls except the append-only store and the sticky session taint (P-16).
- Session taint is sticky (`taint()` never reverts). `ctx.sessionTainted` passed to core = session.tainted OR `ctx.sessionTainted === true`. A tool registered with `taintsSession: true` taints the session after a **successful** call (for retrieval-like tools). Calls through `guard.call` without a session use an ephemeral session (taint only via per-call ctx).
- The guard never exposes the tool functions. `Object.keys(guard)` contains only the public API.
- On creation the guard appends a durable `policy_activate` event (`outcome: { policy_version, mode, rule_count, tool_names_hash }`) if the store's latest `policy_activate` has a different policy_version or mode; `createGuard` throws if that append fails. `monitor_only` activation additionally writes one line to the secondary sink.

### 2.1 Call algorithm (normative order)
0. `decision_id = randomUUID()`, `execution_id` per `call` (session id when sessions are used + counter). Any unexpected exception in the guard ⇒ treated as `engine_error`: best-effort audit, **never execute**, return blocked `unavailable`.
1. Tool not present in `tools` ⇒ deny `unknown_tool` (even if the policy would permit). Tool present but unknown to the policy ⇒ core returns `unknown_tool`.
2. `const { decision, snapshot } = evaluate(policy, { tool, args, ctx })` — exactly once. `latency_us` = hrtime delta around this call only.
3. Let `info = toolInfo(policy, tool)`; if undefined ⇒ defaults `{ risk: "high", external_effect: true, read_only: false, fail_mode: "closed" }`.
4. **Deny path** (`decision.effect === 'deny'`) and `policy.mode === 'enforce'`: `appendBestEffort(decision event)`; return blocked with the public reason (§2.2). The tool is **not** invoked.
5. **monitor_only** (`policy.mode === 'monitor_only'`): the decision event is appended durably with `enforcement='monitor_only'` and `effect` = the computed effect (would-be); if `snapshot` is null (invalid request) the call is still blocked (`invalid_request`); otherwise the tool executes with `snapshot.args` regardless of effect. If the durable append fails, apply step 6's failure rule.
6. **Permit path** (enforce): `store.append(decision event)` **synchronously and durably before executing**. On `StoreError`: if `info.fail_mode === 'open_on_audit_failure'` (core guarantees this implies low risk + read-only) ⇒ write a `{"prysm":"fail_open",...}` line (tool, decision_id, code only) to the secondary sink and execute; otherwise ⇒ blocked `unavailable`, tool not invoked. **Engine errors and deny decisions are never fail-open.**
7. Execute: `await fn(snapshot.args)` — the **frozen snapshot args**, never the caller's object. Tool exceptions are caught: result `{ ok:false, blocked:false, error:"tool_error" }`; the message/stack are never logged or returned.
8. `appendBestEffort(tool_result event)`: `decision_id` link, `outcome: { status: "ok"|"error", error_class?, result_type, result_len, result_hmac }` (never the result value).
9. Return `{ ok: true, value, decision_id }`. The returned value is **untrusted data** (documented); only `taintsSession` tools change the session state automatically.

### 2.2 Public reason mapping (DEC-05)
core `denied_by_rule`, `default_deny`, `tainted_session` ⇒ `denied`; `unknown_tool` ⇒ `unknown_tool`; `invalid_args`, `invalid_request`, `limit_exceeded` ⇒ `invalid_request`; `engine_error`, `audit_unavailable` ⇒ `unavailable`. Detailed reasons, rule ids and policy version appear only in the store (and `explain` in M4). The agent-facing result contains no rule ids, no values and no policy version.

### 2.3 Decision event content
`kind='decision'`, `id=decision_id`, `agent_id`, `user_hmac=hmac("user", userId)`, `session_id`, `tool`, `effect`, `enforcement`, `rule_ids` (all matched deny ids then permit ids), `reason_code` (core's), `policy_version`, `request_digest=hmac("request", decision.request_digest)`, `args_hmac=hmac("args", JCS(snapshot.args))` (null if no snapshot), `args_redacted`, `risk`, `latency_us`, `session_tainted` (0/1), `provenance_asserted` (labels from ctx, or `{"_":"untrusted:unknown"}` when none given), `engine_version`.

## 3. Required tests (names are the acceptance evidence for A-01, A-05, A-06, A-13, A-16, A-18-part)
Store: append/iterate/head/count; chain recomputation independent of the writer (test recomputes with its own code); mutate-row / delete-middle / reorder / tail-delete (tail detected only with anchor) / full-chain rewrite (detected only with external anchor) — tests open the DB raw and drop triggers to simulate an attacker; schema_version mismatch; concurrent writers (≥4 child processes × 100 appends each ⇒ linear chain, exact count, no fork); busy timeout bounded; prune+checkpoint verifies, prune rollback on error; size caps and log-injection strings (`\n{"kind":"decision"}`, ANSI escapes) stored as data; HMAC key file creation, reuse across reopen, digests differ for different keys, plain SHA-256 of a low-entropy value does not match `args_hmac`.
Guard: **A-01** denied tool invoked 0 times (call counter) for default-deny, rule-deny, unknown-tool, tainted-session, invalid args; permit invokes exactly once with the frozen snapshot (identity: not the caller's object; caller mutation before/after/during an `await` does not change what the tool received); decision row committed **before** the tool runs (tool inspects the store during execution and sees its own decision row); fault injection matrix over {store.append throws on decision, throws on tool_result, tool throws, tool rejects asynchronously} × {high-risk closed, low-risk open_on_audit_failure} ⇒ expected execute/block, expected secondary-sink lines, never a raw value; crash simulation between decision and result ⇒ `verify()` warning `outcome_unknown`; forced engine error ⇒ blocked `unavailable`, no execution, event recorded (**A-06**); ctx interleaving with 50 concurrent calls with distinct ctx across awaits each decided on its own ctx; per-call ctx with `agentId` key ⇒ blocked invalid_request; sticky session taint, `taintsSession` tool, tainted + external_effect ⇒ denied; monitor_only semantics (executes, would-be effect recorded, activation line on sink, invalid request still blocked); untagged provenance recorded as untrusted:unknown; **A-05 canary**: a unique secret in args/result/ctx.userId/error text appears in **zero bytes** of the DB file (incl. WAL), the key-independent exports, the secondary sink and returned errors, except in `rawFields` after masking rules; unknown policy tool ⇒ deny; tool registered in guard but missing from policy ⇒ deny.

## 4. v1.1 amendments (DEC-23; from the blind test-plan review). These supersede earlier text where they conflict.
**Store**
1. **Prune/verify (A1, A2, A24).** `checkpointAndPrune` prunes only the **longest seq prefix** whose rows all have `ts_ms < beforeTsMs` (never a non-prefix). The checkpoint row is appended at the tail (seq N+1) with `outcome: { pruned_through_seq, pruned_last_hash, pruned_count }`. Verify's start rule: the first retained row has seq 1 with the genesis `prev_hash`, **or** seq k>1 such that a retained `checkpoint` row exists with `pruned_through_seq == k-1` and `pruned_last_hash == first_row.prev_hash`; otherwise `unexpected_first_row`. `verify` adds warning `history_pruned` (seq of the checkpoint) whenever a checkpoint exists. `openStore` resets `prune_open` to `'0'` and `verify` warns `prune_flag_reset` if it had to.
2. **Genesis/anchors (A4, A22, A23).** Per-store random nonce: `meta.nonce` = 16 random bytes hex; `genesis_hash = sha256("prysm-genesis-v1:" + nonce)`. `Anchor = { genesis_hash, head_seq, head_hash, ts_ms }` (no count). Empty store: `head()` null, `count()` 0, `anchor()` = `{ genesis_hash, head_seq: 0, head_hash: genesis_hash, ts_ms }`, `verify()` ok. `verify({anchor})`: `genesis_hash` must match (else `anchor_mismatch` seq 0); if `anchor.head_seq` ≥ first retained seq, the row with that seq must have `hash == anchor.head_hash`; if it falls inside a pruned range: when it equals `pruned_through_seq` of a retained checkpoint compare to `pruned_last_hash`, otherwise emit warning `anchor_pruned` (not an error). A head_seq above the store head ⇒ `anchor_mismatch`. `guard.close()` writes an `{"prysm":"anchor",...}` line (genesis_hash, head_seq, head_hash) to the secondary sink.
3. **Round-trip safety (A5).** Before hashing/binding, every text field is sanitised by one function: NUL and lone surrogates → U+FFFD, truncation by **code point** (≤256 code points *including* the `…[trunc]` marker), no other mutation. Integers must be safe integers else `StoreError invalid_event`. The hash is computed over exactly the sanitised values bound to SQLite, and `verify` recomputes over what SQLite returns; add a property test (random strings incl. emoji, lone surrogates, NUL, combining marks) proving append→verify never reports a false `hash_mismatch`.
4. **Seq assignment (A6).** Inside `BEGIN IMMEDIATE`: `seq = max(COALESCE(MAX(events.seq),0), COALESCE((SELECT seq FROM sqlite_sequence WHERE name='events'),0)) + 1`, inserted explicitly (never reused after tail deletion).
5. **Warnings (A7, A8).** Decision rows written for a call that **will execute the tool** carry `outcome.will_execute = true`. `verify` warns `outcome_unknown` (at the decision's seq) when such a row has no `tool_result` row with `decision_id = id`, there are ≥1 later rows, and `newest.ts_ms - row.ts_ms ≥ graceMs` (default 10000; configurable in `verify`), and warns `orphan_result` (a tool_result whose decision_id matches no decision) and `duplicate_result` (more than one result for a decision). Duplicate `id` on append ⇒ `StoreError duplicate_id`.
6. **Keys (A11, A38/39).** `opts.keyPath` (default `<path>.key`, recommended to place outside the DB directory). Key file created with flag `wx` and mode `0o600`; on `EEXIST` re-read. Key must be exactly 32 bytes; provided `hmacKey` must be ≥ 32 bytes; otherwise `StoreError key_invalid`. If `meta.key_id` exists and the loaded key's id differs, or the key file is missing/corrupt for an existing store ⇒ `StoreError key_mismatch` (never silently regenerate).
7. **Clock (A13).** `openStore({ clock })` (default `Date.now`); readings must be finite non-negative integers else `invalid_event` (guard maps to `unavailable`). The clock is never used for ordering; prune uses the seq-prefix rule only.
8. **Size caps (A25).** Text fields as in item 3. A JSON column > 4096 bytes serialised ⇒ `{"truncated":true,"bytes":N}`. `rule_ids` stores at most 16 ids then `"…+N"`. If the whole row still exceeds 16 KiB, replace `args_redacted`, `provenance_asserted`, `model_meta`, `outcome` with truncation markers in that order until it fits; otherwise `invalid_event`.
9. **Best-effort circuit breaker (A26).** `appendBestEffort` uses a busy timeout of `min(busyTimeoutMs, 250)`; after 3 consecutive failures it skips store attempts for 5000 ms (hrtime-based) while still writing the sink line per dropped event.
10. **Paths (A31).** `":memory:"` is rejected unless `hmacKey` is supplied (then no key file); a missing parent directory ⇒ `StoreError io`. `openStore` on a schema_version other than 1 ⇒ `StoreError corrupt`. Invalid `beforeTsMs` (NaN, negative, non-number) ⇒ `invalid_event` with no change. Verify error `seq`: `bad_genesis` → first row's seq; `anchor_mismatch` → `anchor.head_seq`.
11. **Redaction (A19, A20).** `args_redacted` has entries only for argument names **declared in the policy for that tool**; all other keys collapse into `"_undeclared": <count>`. `len` stays (documented residual leak of length). Result serialisation: `result_type` ∈ `string|number|boolean|object|array|null|undefined|bigint|other`; `result_hmac = hmac("result", jcs(value))` when `value` is plain JSON ≤ 1 MiB serialised, else null; `result_len` = serialised length or null. `error_class` must match `^[A-Za-z0-9_]{1,64}$` else `"Unknown"`; a non-Error throw ⇒ `"NonError"`. A 5 MB string result must not throw.

**Guard**
12. **Order of checks before `evaluate` (A15, A18, A21).** (a) Validate `CallContext`: unknown keys (including `agentId` and `sessionId`) ⇒ blocked `invalid_request`; (b) tool lookup uses **own-property** check (`Object.hasOwn`) on a registry that is **copied and frozen at creation**; not found ⇒ `unknown_tool`; (c) `evaluate`. Each rejection before `evaluate` still writes a best-effort decision row: `effect: deny`, `reason_code` `invalid_request`/`unknown_tool`, digests null, and `tool` = the name only if it is an own key of the registry or policy, else `"?"` with `outcome.tool_hmac = hmac("tool", name)`. `CallContext` no longer has `sessionId`; sessions exist only via `guard.session(id?)` (id must match `^[A-Za-z0-9_.:-]{1,64}$`, default random; the same id returns the same session object). `taintsSession` must be exactly `true`. Calls via `guard.call` use an ephemeral session whose taint cannot leak to later calls.
13. **monitor_only (A16).** Never executes when `snapshot` is null or the core reason_code ∈ {`engine_error`, `invalid_args`, `invalid_request`, `limit_exceeded`, `unknown_tool`}; executes otherwise (would-be `denied_by_rule`, `default_deny`, `tainted_session`, or permit). The `monitor_only` sink line is written on **every** `createGuard`.
14. **Taint ordering (A17).** On a successful `taintsSession` tool call, the session is tainted synchronously immediately after the tool resolves, before the result row is appended and before the guard returns. Calls already decided are unaffected (documented).
15. **Fail-open budget (A27).** After 5 consecutive fail-open executions in one guard, `fail_mode: open_on_audit_failure` tools fail **closed** until a durable append succeeds again; each fail-open writes the sink line.
16. **Sink hygiene (A10).** The secondary sink is wrapped in try/catch (a throwing sink never changes the outcome); lines are single-line JSON with every string field sanitised and ≤ 64 chars; the only allowed shapes are `{"prysm":"fail_open","tool","decision_id","code"}`, `{"prysm":"audit_write_failed","code","kind","id"}`, `{"prysm":"monitor_only","policy_version"}`, `{"prysm":"anchor","genesis_hash","head_seq","head_hash"}`, `{"prysm":"audit_skipped","kind","id"}` (breaker). `tool` appears only for own keys of registry/policy.
17. **Misc rulings.** `policy_activate` rows: `agent_id` = guard agent, `effect` null, `enforcement` from policy mode, `tool` null. Taint reason text is **not stored**. `guard.close()` does not close the store (caller owns it); calls after close ⇒ blocked `unavailable`; double close is fine. The value returned to the caller is exactly what the tool returned (untrusted). Public reason `invalid_request` vs `denied` and `unavailable` are an accepted small information oracle (documented). The deny-path audit is best-effort and may be lost under store failure (accepted; the sink line records it). `ctx.provenance` is host-asserted (documented trust boundary).

## 5. v1.2 amendments (DEC-24; M2 gate pass 1: security-engineer M2-01..09 + critical-reviewer MAJOR-1..4). Supersede earlier text where they conflict.
**Verify / chain (M2-01, M2-02)**
1. **Anchor shape.** `verify({anchor})` first validates the anchor: `genesis_hash` and `head_hash` are 64-hex strings, `head_seq` is a safe integer ≥ 0, and `head_seq == 0` requires `head_hash == genesis_hash`; any violation ⇒ error `anchor_mismatch` (seq 0) and no further anchor logic. `anchor_pruned` (warning) is emitted only when `0 < head_seq < first retained seq` **and** a retained checkpoint exists whose range covers it and it does not equal `pruned_through_seq`; otherwise (no checkpoint, or head_seq not covered) it is `anchor_mismatch`.
2. **Pruned history is not silently OK.** `verify()` returns `ok:false` with error `history_pruned` (seq of the checkpoint) unless the caller passes `allowPruned: true` **or** `expectPruned: { through_seq, last_hash }` matching a retained checkpoint's `outcome`. `checkpointAndPrune` returns `{ pruned, checkpointSeq, through_seq, last_hash }` and writes a `{"prysm":"checkpoint","genesis_hash","through_seq","last_hash"}` line to the secondary sink (sanitised, allowlisted) so the operator holds an external record. `checkpointAndPrune` is a **no-op** (returns `pruned: 0`, appends nothing) when no rows are eligible, and it enforces a retention floor: `beforeTsMs` must be ≤ `clock() - minRetainMs` (default 24 h, option `minRetainMs`) unless `{ force: true }`.
3. **orphan_result.** Suppressed for a result whose `decision_id` refers to a decision with seq ≤ the retained checkpoint's `pruned_through_seq` (decision pruned).
**Keys (M2-03)**
4. On win32 after creating the key file the store tries to restrict it to the current user (`icacls <file> /inheritance:r /grant:r <USERNAME>:(R,W)`, no shell string concatenation of untrusted data — args array). `store.keyProtection(): "acl" | "mode_0600" | "unprotected"` reports the result; `verify()` warns `key_unprotected` when `"unprotected"`, and warns `key_colocated` when the key path is in the same directory as the DB file. README must state that the key beside the DB means DB access ⇒ offline brute-force of low-entropy digests; place `keyPath` elsewhere.
**Guard (M2-04, M2-05, M2-06, M2-07 / MAJOR-1, MAJOR-3, MAJOR-4)**
5. **Short busy cap on best-effort writes.** The store exposes `appendShort(ev)` = `append` with busy timeout `min(busyTimeoutMs, 250)`; the guard's best-effort path (deny rows, result rows, pre-evaluate rows) uses `appendShort` (through `makeBestEffort`, so injected faults still apply). A guard-level test with a held `BEGIN IMMEDIATE` lock asserts a deny call returns in < 600 ms. The permit path keeps the full `busyTimeoutMs` and the docs say so; guard default `busyTimeoutMs` for stores it opens is 2000.
6. **Best-effort row rate limit.** The guard caps *best-effort* rows (deny, pre-evaluate, tool_result) to `maxBestEffortRowsPerWindow` (default 1000) per 60 s window (`clock`-independent: hrtime). Excess rows are dropped and counted; at most one `{"prysm":"audit_skipped","kind":"rate_limit","dropped":N}` sink line is written per window, and the drop count is recorded in the next row that is written (as `outcome.dropped_before`). Permit decision rows are never rate-limited.
7. **Fail-open** triggers only on `busy` and `io` store errors (not `invalid_event`, `duplicate_id`, `key_*`, `corrupt`). Budget option `failOpenBudget` (default 5, 0 disables fail-open entirely).
8. **Sessions.** Cap 10 000 live sessions; at the cap, **untainted** least-recently-used sessions are evicted (a recreated session starts untainted, so no taint is shed); tainted sessions are never evicted. If every session is tainted and the cap is reached, `guard.session()` throws `GuardError` (`code: "session_limit"`). Add `session.close()` (releases an untainted session; closing a tainted session marks it closed, further calls ⇒ blocked `unavailable`). `session.taint()` appends a best-effort audit row? **No** (Low, deferred): document that taint is in-memory only, not audited, and lost on restart.
9. **Provenance copy** uses `Object.create(null)` + `Object.defineProperty`; a `__proto__` key is passed to core as an ordinary key and rejected there as `invalid_request`.

## 6. v1.3 amendments (DEC-25; M2 gate re-verification: security-engineer M2-10..M2-14). Supersede earlier text where they conflict.
1. **expectPruned is strict (M2-10).** `verify({ expectPruned })` takes an array of `{ through_seq, last_hash }` (a single object is accepted as a one-element array) — the values the operator logged from the sink's `checkpoint` lines. Rules: every retained checkpoint row must equal one expected entry **and** the effective boundary must hold (`first_retained.seq - 1 == through_seq` and `first_retained.prev_hash == last_hash` for the checkpoint that justifies the start); every retained checkpoint not in the expected list is an **error** `history_pruned` at its seq; an expected entry with no matching retained checkpoint is an error `checkpoint_missing`. `allowPruned: true` downgrades `history_pruned` to a warning but is documented as "accept any pruning — development only"; `verify` always returns the list `checkpoints: [{ seq, through_seq, last_hash }]` so callers can log and compare. A forged second checkpoint (legit prune through 5, forged through 12) must fail under `expectPruned` of the legit one.
2. **Key ACL honesty (M2-11).** The principal comes from `os.userInfo().username` (not env vars); well-known group names (`Everyone`, `Users`, `Authenticated Users`, `BUILTIN\*`, `NT AUTHORITY\*`, `SYSTEM` as the *grantee*) are rejected. After `icacls` the store re-reads the ACL (`icacls <file>`) and reports `"acl"` only if exactly one principal entry is present, equals the current user, and inheritance is removed; on every open it re-reads the ACL instead of trusting `meta` (meta is a hint only; a mismatch ⇒ `key_unprotected` warning). Tests inject the ACL reader.
3. **Separate best-effort budgets (M2-12).** Three independent per-window budgets: `pre_evaluate` rows (unknown tool, invalid request/ctx) default 200; `policy_deny` rows default 1000; `tool_result` rows default 1000 (options `maxPreEvaluateRowsPerWindow`, `maxDenyRowsPerWindow`, `maxResultRowsPerWindow`; the single `maxBestEffortRowsPerWindow` option is removed). Each exhausted class increments its own counter, writes at most one `audit_skipped` sink line per window per class, and carries the count in the next written row's `outcome.dropped_before` (per class: `{ pre_evaluate: n, policy_deny: n, tool_result: n }` when non-zero). A flood of one class must never suppress rows of another class. Permit decision rows remain uncapped.
4. **Single session state per id (M2-13).** The guard keeps one state object per session id in its map; handles resolve their state through the map on every use. A handle whose state was LRU-evicted re-registers its own state when used, unless the id has meanwhile been re-registered, in which case the handle uses the **registered** state and taint is merged with `tainted ||=` both ways. The scenario (A=session('a'), evict, B=session('a'), B.taint(), A.call(external-effect tool)) must be blocked through A.
5. **Admin facet (M2-14).** `Guard` = `{ call, session, close }` only. A second export `createGuardWithAdmin(opts) → { guard, admin }` where `admin = { setTools(registry) }`; `createGuard(opts)` returns only `guard`. `setTools` appends a durable `policy_activate` row (`outcome: { event: "tools_replaced", tool_names_hash }`) **before** swapping; if the append fails it throws and the registry is unchanged. Documented: whoever holds the `admin` object is trusted; give agent code only `guard.call`/`session`.

### Amendment (DEC-34): decision outcome deny_n
Decision rows written by the guard carry `outcome.deny_n` (integer): the number of deny-rule ids at the start of `rule_ids` (deny ids first, then permit ids); 0 for pre-evaluate and denyUnexposed rows. Consumers use it to name only deny rules as the cause of a block (REPORT-SPEC section 5.1-5.3). Rows without it are legacy rows.

## 8. v1.4 amendment (DEC-39; found by the M5 benchmark audit)
**Result rows of executed permits are not rate-limited.** The M2-12 budgets (pre-evaluate, policy-deny, tool_result; §6.3) stop an agent from drowning evidence of *denied or invalid* attempts. A `tool_result` row, however, exists 1:1 for a permit decision whose durable row is already written and is never rate-limited, so metering result rows adds no protection and, above the budget, leaves permitted calls without outcomes (spurious `outcome_unknown` warnings, understated audit cost). Therefore: the guard writes the `tool_result` row for every executed call (at most one per decision) outside the `tool_result` budget; it stays **best-effort** (short busy timeout, circuit breaker, sink line on failure) and keeps the `maxResultRowsPerWindow` option name only as an optional hard ceiling that defaults to **unlimited** (`Infinity`); the pre-evaluate and policy-deny budgets are unchanged. `dropped_before` accounting for the remaining classes is unchanged. Tests: 3 000 sequential permitted calls produce 3 000 result rows and no `outcome_unknown`; the pre-evaluate and policy-deny flood tests of M2-12 still pass; a configured finite `maxResultRowsPerWindow` still drops and counts excess result rows.
