| DEC-01 | **MCP stdio proxy is in the MVP as the enforcing mode** (separate process; agent host cannot reach tool server credentials/audit DB). In-process `guard()` stays as a thin convenience over the same `decide()` core. Guarantee stated precisely: *PRYSM enforces policy on calls routed through it; it does not stop code that bypasses it, and the proxy is only enforcing if deployment makes it the sole path to the tool.* | In-process only (draft v1) | Architect B1 / security §2: in-process is a bug-catcher vs hostile same-process code (A2); T2 was a convention not a control | Proposed |
| DEC-02 | **Policy format: strict JSON** (YAML deferred). Deny-overrides semantics only: any matching deny wins, else any matching permit, else default deny. **No priority, no specificity.** Effects: `permit`/`deny`. `redact` removed from policy effects (redaction lives only in the audit path). Schema carries `policy_schema_version`. Unique rule ids, reject duplicate/unknown keys, `__proto__`, non-printable/zero-width/bidi chars; ids charset `[A-Za-z0-9_.-]`. Absent/wrong-type attribute ⇒ predicate false (deny rules fail safe: absent attribute on a `deny` predicate marks `engine_error`→deny). Version = SHA-256 of JCS (RFC 8785) of parsed policy. Read file bytes once. No hot reload (restart to activate), pin optional hash. Size/depth/rule-count limits; linear glob matcher; no user regex. Differential test vs Cedar as oracle for the shared subset (test-only). | Cedar/OPA runtime; YAML; priority+specificity | Architect B2/M2, security P-06/P-13/P-14 | Proposed |
| DEC-03 | **Audit semantics.** Allow on side-effecting tool: decision record committed synchronously and durably (SQLite `synchronous=FULL`) *before* execution; on failure → deny `audit_unavailable`. Deny events best-effort (never convert deny). `tool_result` row is second best-effort append; crash between ⇒ "decision recorded, outcome unknown", flagged by `verify-chain`. **No fail-open on `engine_error`.** Fail-open exists only as explicit per-tool opt-in for *audit-write failure* of low-risk read-only tools, with a secondary stderr record. Unknown tool ⇒ deny; missing risk/fail_mode ⇒ closed. Chain: SHA-256(prev_hash ‖ JCS(row sans hash)), defined genesis, single writer via `BEGIN IMMEDIATE` (concurrency test), UPDATE/DELETE triggers (speed bump), `prysm anchor` prints head+count, retention writes a checkpoint event, per-install HMAC for `args_digest`, `schema_version` meta table, ms-UTC timestamps, hrtime for latency, `session_id`/hashed `user_id`/`engine_version`/`provenance_asserted` columns. Async/batched writes only in benchmark comparison, not an MVP mode. `monitor_only` defined: decide+log both would-be and actual outcome, always execute; included in policy hash, activation logged loudly. | Async writes; fail-open default | Architect B3/M3/m7, security P-03/P-07/P-14 | Proposed |
| DEC-04 | **Provenance demoted**: session-level taint flag (once untrusted content entered context, `external_effect`-tagged tools restricted) + optional per-argument tags, both *asserted by host* and recorded as `provenance_asserted`. Not marketed as taint tracking or as the differentiator until developer interviews validate it. Proxy mode gets taint only via an explicit control channel (design in M3, else in-process only). | Per-arg tags as headline | Architect M1, security P-02/P-09 | Proposed |

| DEC-06 | **Single npm package**, internal dirs `src/core, src/store, src/proxy, src/cli, src/report`; core import-graph test (no net/http/child_process/fetch/store imports). `@prysm/models` and `runModel()` cut from core; mock model and optional real adapter live in `examples/`.
